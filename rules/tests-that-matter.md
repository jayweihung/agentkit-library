# 只加有用的測試

**專案自己有測試規則時，以專案的為準**（例如專案規定新功能和修 bug 都要附測試、要有守衛測試）。這條只在專案沒說的時候用。

專案沒規定時，預設不加測試。沒用的測試要花時間維護，抓到的問題卻很少。

要加的話，要同時符合：
1. **把你的改動拿掉，這個測試就會失敗。** 拿掉還會過的，不是在測你的改動。
2. **預期值寫死在測試裡**，不是用產品程式、翻譯檔或假物件算出來的（不然兩邊錯得一樣，測試照樣過）。
3. 放在**真正負責這個行為的那一層**測，不要每一層各測一次。

通常不值得測：文案或翻譯、CSS 樣式名稱、常數、第三方套件本身、內部的私有狀態、時間長短、呼叫了幾次。碰到這種測試，不要自己刪：專案的測試是專案的，跟使用者說你覺得它沒用、為什麼，由使用者決定。

修 bug 時，先寫一個重現這個 bug、現在會失敗的測試，修好後它變成會過，這種最值得留。
